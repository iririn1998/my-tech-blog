「キャッシュが効かない」「キャッシュが消えない」— fetch まわりの不具合報告は、たいていどの層のキャッシュかが特定されないまま議論が始まります。まず層を分けましょう。

## 3つの層

ブラウザの HTTP キャッシュ、Service Worker の Cache Storage、そしてフレームワークが被せる独自キャッシュ。この3層は無効化の方法も生存期間も別物です。障害調査ではどの層のヒットかを DevTools の Size 列で見分けるところから始めます。

## Cache-Control の実務指針

静的アセットは `max-age=31536000, immutable`、API レスポンスは `no-store` か短い `s-maxage` + CDN 側制御。中途半端な `max-age` をアプリの API に付けるのが、経験上いちばん事故につながります。

## フレームワークの独自キャッシュ

fetch をラップして独自のキャッシュを被せるフレームワークでは、HTTP ヘッダーと設定の優先順位を必ずドキュメントで確認します。両者が食い違うと、この記事の冒頭のような不具合報告が生まれます。
